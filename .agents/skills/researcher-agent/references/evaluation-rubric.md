# 研究质量评估标准

## LLM-as-Judge 评估 Rubric

### 评估维度

| 维度 | 权重 | 评分标准 |
|------|------|---------|
| 事实准确性 | 30% | 论点是否有可靠来源支撑 |
| 专业深度 & 可读性 | 30% | 实用价值、信息密度、数据标注来源、清晰务实 |
| 完整性 | 20% | 是否覆盖了所有请求的方面 |
| 结构清晰度 | 20% | --- 分割线分块、每块自洽、幻灯片友好 |

### 评分等级

```
1.0 = 优秀 (Pass)
0.7 = 良好 (Pass with minor issues)
0.5 = 及格 (Needs improvement)
0.3 = 不及格 (Significant issues)
0.0 = 失败 (Complete failure)
```

---

## 详细评估标准

### 1. 事实准确性 (30%)

| 分数 | 描述 |
|------|------|
| 1.0 | 所有论点都有可靠来源支撑，无事实错误 |
| 0.7 | 绝大多数论点有来源支撑，可能有 1-2 个未支撑的小论点 |
| 0.5 | 部分关键论点缺乏来源或有小的事实错误 |
| 0.3 | 多处事实错误或关键论点无来源 |
| 0.0 | 严重事实错误或虚构信息 |

**检查点**：
- [ ] 每个关键论点都有引用
- [ ] 数据点有明确来源
- [ ] 没有编造的信息

---

### 2. 专业深度 & 可读性 (30%)

| 分数 | 描述 |
|------|------|
| 1.0 | 清晰务实、信息密度高，每个论点有数据或实际案例支撑。读起来像一个务实开发者的实用备忘录，读完知道怎么用、怎么选 |
| 0.7 | 基本清晰，但部分段落缺乏实用价值或证据支撑 |
| 0.5 | 能读懂但偏浅或偏学术，实用信息不够，像科普文或纯技术深潜，缺乏实操指导 |
| 0.3 | 大段堆砌，缺乏分析，读着像百科条目或公司宣传册 |
| 0.0 | 完全是机器生成的流水账，既无深度也无结构 |

**检查点**：
- [ ] 开头直击要害，不是"本文将..."
- [ ] 段落精炼（2-5 句），论点+证据+推论
- [ ] 关键数据标注来源
- [ ] 每个论点有数据、实际案例或因果分析支撑
- [ ] 技术概念首次出现有定义或上下文说明
- [ ] 口语化过渡词（"说白了"等）全文不超过 2 次
- [ ] 没有公司宣传式描述（star 数、协议、融资、背景故事）
- [ ] 技术细节适度，没有为了显深而过度解释内部机制

---

### 3. 完整性 (20%)

| 分数 | 描述 |
|------|------|
| 1.0 | 完整覆盖所有请求方面，无明显遗漏 |
| 0.7 | 覆盖主要方面，次要方面略有遗漏 |
| 0.5 | 部分请求方面未覆盖 |
| 0.3 | 大量请求内容缺失 |
| 0.0 | 与请求几乎无关 |

**检查点**：
- [ ] 回答了用户的核心问题
- [ ] 覆盖了隐含的子问题
- [ ] 提供了必要的背景信息

---

### 4. 结构清晰度 (20%)

| 分数 | 描述 |
|------|------|
| 1.0 | 每个 section 用 --- 分隔，每块自洽可独立成幻灯片，逻辑流畅 |
| 0.7 | 有分割线分块，个别块内容偏多或不够自洽 |
| 0.5 | 有结构但生硬，像列清单，或缺少分割线 |
| 0.3 | 东一榔头西一棒子，--- 使用混乱 |
| 0.0 | 完全无结构，一大坨连续文字 |

**检查点**：
- [ ] 每个 section 之间有 --- 分割线
- [ ] 每个 --- 块内容自洽，独立成页也能看懂
- [ ] 3-5 个 section，不多不少
- [ ] 没有参考文献列表
- [ ] 配图规划 section 已追加在结论之后
- [ ] 5 张配图的场景描述互相有区分

---

## 评估 Prompt 模板

```markdown
你是一个研究质量评估员。请评估以下调研文章。

**研究查询**：{original_query}

**调研文章**：
{article}

**评估维度**：

1. **事实准确性** (30%)：论点是否有可靠来源支撑？
2. **专业深度 & 可读性** (30%)：实用价值是否足够？信息是否清晰有据？数据是否标注来源？读完是否知道怎么用？有无公司宣传式内容？
3. **完整性** (20%)：是否覆盖了所有请求的方面？
4. **结构清晰度** (20%)：--- 分割线分块是否合理？每块是否自洽可独立成幻灯片？

**输出格式**：

```json
{
  "scores": {
    "factual_accuracy": 0.0-1.0,
    "readability": 0.0-1.0,
    "completeness": 0.0-1.0,
    "structure_clarity": 0.0-1.0
  },
  "weighted_score": 0.0-1.0,
  "pass_fail": "pass" | "fail",
  "issues": ["issue1", "issue2"],
  "strengths": ["strength1", "strength2"],
  "recommendations": ["rec1", "rec2"]
}
```

**评分说明**：
- 加权分 ≥ 0.7 = Pass
- 加权分 < 0.7 = Fail
```

## 人工评估检查清单

### 结构检查
- [ ] 每个 section 之间有 --- 分割线
- [ ] 每个 --- 块内容自洽，能独立成幻灯片
- [ ] 3-5 个 section，不多不少
- [ ] 没有参考文献列表

### 专业深度检查
- [ ] 开头直击要害，切入核心论点或关键数据
- [ ] 每个论点有数据、机制或因果分析支撑
- [ ] 关键数据标注了来源机构/报告
- [ ] 技术概念首次出现有定义或上下文说明
- [ ] 段落精炼，论点+证据+推论
- [ ] 口语化过渡词全文不超过 2 次

### 内容检查
- [ ] 回答了用户核心问题
- [ ] 关键数据有来源支撑
- [ ] 没有明显的信息缺口

## 常见问题与扣分

| 问题 | 扣分 |
|------|------|
| 虚构事实或数据 | -0.5 |
| 关键论点无来源 | -0.3 |
| 没有 --- 分割线分块 | -0.3 |
| 某个 --- 块内容过多，无法独立成幻灯片 | -0.2 |
| 开头写"本文将探讨..." | -0.2 |
| 全文没有精确数据或来源标注 | -0.2 |
| 语气过于口语化，"说白了"等出现超过 2 次 | -0.2 |
| 使用过时信息（>2年）未标注 | -0.2 |
| 文末堆参考文献列表 | -0.2 |
| 段落超过 6 行 | -0.1 |
| 数据堆砌成表格而非融入叙述 | -0.1 |
| 出现"值得一提的是"等套话 | -0.1 |
| 出现公司宣传式描述（star数、协议、融资、背景故事）且与使用决策无关 | -0.2 |
| 过度深挖内部机制，读者实际不需要知道这些 | -0.1 |
| 配图规划 section 缺失 | -0.2 |
| 5 张配图的场景描述雷同，缺乏差异化 | -0.1 |
| 配图提示词使用英文关键词格式而非中文自然语言 | -0.1 |
