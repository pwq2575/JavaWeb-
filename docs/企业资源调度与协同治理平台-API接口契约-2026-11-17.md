## 1. 通用约定

### 1.1 统一响应体

```json
{ "code": 0, "message": "ok", "data": { } }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | int | `0` 成功；非 0 为业务错误码（见 §1.6） |
| message | string | 面向用户的中文提示（可直接 toast） |
| data | object / array / null | 业务数据；无返回体时传 `null` |

### 1.2 HTTP 状态码与业务码的关系

- HTTP 2xx 且 `code=0`：成功。
- HTTP 4xx/5xx 且 `code≠0`：失败，前端拦截器统一 toast `message`，401 额外清令牌并跳登录。
- 前端**只以 `code` 判断业务成功**，不依赖 HTTP 状态做分支（导出接口除外，见 §10）。

### 1.3 鉴权

- 除 `/auth/login`、`/auth/register` 外，所有接口要求请求头：
  `Authorization: Bearer <JWT>`
- JWT 载荷：`{ "sub": "<userId>", "role": "USER|ADMIN", "iat": …, "exp": … }`，有效期 **2 小时**。
- 令牌失效/缺失 → HTTP 401 `code=40100`；前端跳 `/login?redirect=<当前路由>`。
- 角色不足 → HTTP 403 `code=40300`。

### 1.4 分页与排序

- 请求参数：`page`（从 1 开始，默认 1）、`size`（默认 20，最大 100）。
- 响应 `data`：`{ "records": [], "total": 123, "page": 1, "size": 20 }`。
- 排序参数 `sort=field,asc|desc`，**仅允许白名单字段**（每资源单独列出），非法字段忽略并回退默认排序，不抛错。

### 1.5 数据格式

| 类型 | 约定 | 示例 |
|---|---|---|
| 时间 | ISO-8601 本地时间（Asia/Shanghai） | `2026-11-17 09:20:00` |
| 日期 | `yyyy-MM-dd` | `2026-11-19` |
| 金额 | number，两位小数（元） | `3800.00` |
| 枚举 | 英文大写字符串（状态码），前端字典映射中文 | `BORROWED` |
| 布尔 | JSON boolean | `true` |
| ID | number（BIGINT 范围内安全，前端按 number 处理） | `1024` |

### 1.6 错误码表

| code | HTTP | 含义 | 典型场景 |
|---|---|---|---|
| `0` | 200 | 成功 | — |
| `40001` | 400 | 参数校验失败 | `@Valid` 不通过，`data` 返回字段错误列表 |
| `40100` | 401 | 未登录 / 令牌失效 | 无 Bearer、令牌过期、账号停用 |
| `40300` | 403 | 无权限 | 普通用户访问 `/admin/**`；操作他人数据 |
| `40301` | 403 | 信誉分不足 | 信誉 < `credit.threshold` 时借高价值资产 |
| `40400` | 404 | 资源不存在 | 资产/预约/申请 ID 不存在 |
| `40900` | 409 | 状态冲突 | 资产已被借出、切片已被占用、重复投票、已有待审批转交 |
| `42200` | 422 | 业务规则不满足 | 续借超 3 次、转交对象不合法、投票已截止、删除有流转记录的资产 |
| `50000` | 500 | 服务器内部错误 | 未捕获异常（不返回堆栈） |

`40001` 的 `data` 示例：

```json
{ "code": 40001, "message": "参数校验失败",
  "data": { "title": "申请名称不能为空", "reason": "理由不能超过 200 字" } }
```

### 1.7 并发与幂等

| 场景 | 策略 |
|---|---|
| 借出 | 条件更新 `UPDATE asset SET status='BORROWED' WHERE id=? AND status='IN_STOCK'`，影响行数 0 → `40900` |
| 场地切片 | 依赖 `uk_reservation_slot`，捕获 `DuplicateKeyException` → `40900`「该时段已被预约」 |
| 重复投票 | 依赖 `uk_vote_user` → `40900` |
| 同一资产多条待审批转交 | 依赖 `uk_transfer_pending` → `40900` |
| 逾期扣分去重 | 依赖 `uk_credit_daily` → 已存在则跳过（不报错） |
| 审批重复提交 | 条件更新 `WHERE status='PENDING'`，影响行数 0 → `40900` |

## 2. 认证 `/auth`

| # | 方法 | 路径 | 角色 | 说明 |
|---|---|---|---|---|
| 1 | POST | `/auth/register` | 匿名 | 注册普通用户并自动登录 |
| 2 | POST | `/auth/login` | 匿名 | 账号密码登录，签发 JWT |
| 3 | GET | `/auth/me` | 登录 | 当前用户资料与信誉分 |
| 4 | POST | `/auth/logout` | 登录 | 退出（可选 Redis 黑名单） |

**1 POST `/auth/register`**

```json
// 请求
{ "username": "zhangsan", "password": "Abc12345", "realName": "张三" }
// 成功 data
{ "token": "eyJhbGciOi...", "expiresIn": 7200,
  "user": { "id": 2, "username": "zhangsan", "realName": "张三",
            "role": "USER", "creditScore": 100 } }
```

| 校验 | 规则 | 失败 code |
|---|---|---|
| username | 3–32 位字母/数字/下划线，唯一 | `40001` / `40900` |
| password | 8–32 位，至少含字母与数字 | `40001` |
| realName | 1–32 字 | `40001` |

**2 POST `/auth/login`** — 请求 `{ "username", "password" }`；成功同注册；账号停用返回 `40100`「账号已停用」；密码错误统一 `40100`「账号或密码错误」（不区分账号是否存在）。

**3 GET `/auth/me`** — `data`：`{ id, username, realName, role, creditScore, status, createdAt }`。

**4 POST `/auth/logout`** — 无请求体；`data: null`。

## 3. 资产 `/assets`

| # | 方法 | 路径 | 角色 | 说明 |
|---|---|---|---|---|
| 5 | GET | `/assets` | 登录 | 资产目录分页（全员） |
| 6 | GET | `/assets/{id}` | 登录 | 资产详情（含是否可借、限制原因） |
| 7 | POST | `/assets` | ADMIN | 新增资产 |
| 8 | PUT | `/assets/{id}` | ADMIN | 编辑资产（在借资产仅允许改描述类字段） |
| 9 | DELETE | `/assets/{id}` | ADMIN | 删除资产（仅限无流转记录；否则 `42200`，改用停用） |
| 10 | POST | `/assets/{id}/borrow` | 登录 | 借出，`due_date = 今天 + borrow.days` |
| 11 | POST | `/assets/{id}/return` | 登录 | 归还（持有者或管理员） |
| 12 | POST | `/assets/{id}/renew` | 登录 | 续借 +1 天（持有者本人） |
| 13 | GET | `/assets/{id}/records` | 登录 | 流转时间线（倒序） |

**5 GET `/assets`**

| 参数 | 类型 | 说明 |
|---|---|---|
| page / size | int | 分页 |
| keyword | string | 编号/名称模糊搜索 |
| status | string | `IN_STOCK` / `BORROWED` / `DISABLED`，空=全部 |
| category | string | 分类过滤 |
| highValueOnly | bool | 仅高价值（value ≥ 500） |
| sort | string | 白名单：`code,name,value,updated_at`，默认 `updated_at,desc` |

`data.records[]` 项：

```json
{ "id": 1, "code": "A-0201", "name": "投影仪 EPSON CB-X06", "category": "电子设备",
  "value": 3800.00, "status": "BORROWED", "highValue": true,
  "holderId": 2, "holderName": "张三", "borrowAt": "2026-11-16 10:00:00",
  "dueDate": "2026-11-19", "overdueDays": 0, "renewCount": 0 }
```

**6 GET `/assets/{id}`** — 在列表字段基础上追加：

```json
{ "description": "含 HDMI 线与遥控器",
  "canBorrow": false,
  "borrowBlockReason": "ASSET_BORROWED",   // ASSET_BORROWED | STATUS_DISABLED | LOW_CREDIT | HIGH_VALUE_LOCKED | null
  "viewerCreditScore": 100, "creditThreshold": 60,
  "recentRecords": [ ... ]                  // 最近 5 条，与 #13 同结构
}
```

> `borrowBlockReason` 由后端统一计算，前端只按枚举映射文案（见 IA §6.5 M-03），**禁止前端自行判断信誉**。

**7 POST `/assets`（ADMIN）**

```json
{ "code": "A-0217", "name": "便携投影幕布", "category": "电子设备",
  "value": 320.00, "description": "80 寸" }
```

必填：`code`、`name`、`category`、`value(≥0)`。`code` 唯一，重复 `40900`。

**8 PUT `/assets/{id}`（ADMIN）** — 同字段；`BORROWED` 状态下忽略 `status`/`holderId` 变更（`42200` 若显式传）。

**9 DELETE `/assets/{id}`（ADMIN）** — 有 `asset_record` 或当前 `BORROWED` → `42200`「存在流转记录，请改为停用」；成功 `data: null`。

**10 POST `/assets/{id}/borrow`** — 无请求体（管理员代借：`{ "userId": 2 }` 可选）。成功 `data` 为资产最新详情。

| 校验 | 失败 code / message |
|---|---|
| 资产不存在 | `40400` |
| 非 `IN_STOCK` | `40900`「该资产已被借出」 |
| `DISABLED` | `42200`「资产已停用」 |
| 高价值且信誉 < 阈值 | `40301`「信誉分不足，暂不能借用高价值资产」 |

**11 POST `/assets/{id}/return`** — 仅持有者或 ADMIN；写入 `asset_record(RETURN)`，资产回 `IN_STOCK`、清空 `holder_id/due_date/renew_count`。

**12 POST `/assets/{id}/renew`**

| 校验 | 失败 code / message |
|---|---|
| 非本人持有 | `40300` |
| `renew_count ≥ 3` | `42200`「续借次数已用完」 |
| 存在待审批转交 | `42200`「有待处理的转交申请，暂不可续借」 |
| 已逾期 | **允许续借**（PRD D10 / IA Q10）：续借成功即停止后续每日扣分，此前已扣不予回补 |

成功：`due_date += 1 天`，`renew_count += 1`，`data.dueDate` 返回新值；若本次续借发生在逾期期间，返回 `data.overdueStopped = true`。

**13 GET `/assets/{id}/records`** — `data`：

```json
[ { "id": 7, "action": "BORROW", "operatorName": "张三", "targetUserName": null,
    "fromStatus": "IN_STOCK", "toStatus": "BORROWED",
    "remark": "张三借出投影仪", "happenedAt": "2026-11-16 10:00:00" } ]
```

排序：`happened_at DESC`（最新在前）。

|---|---|---|---|---|
| 14 | POST | `/transfers` | 登录 | B 向当前持有者 A 发起转交 |
| 15 | GET | `/transfers` | 登录 | 我的转交：`box=incoming`（待我审批）/`outgoing`（我发起的） |
| 16 | PUT | `/transfers/{id}/approve` | 登录（A） | 同意：持有者改为 B，`due_date` 不变，写 TRANSFER 记录 |

**14 POST `/transfers`**

```json
{ "assetId": 1, "toUserId": 3, "applyReason": "张三本周出差，希望由李四继续使用到周五" }
```

|---|---|

| 申请人不是持有者（由 A 代为发起） | 仅 ADMIN 可代发起，否则 `40300` |

成功 `data`：`{ "id": 1, "status": "PENDING" }`。

**15 GET `/transfers?box=incoming&status=PENDING&page=1&size=20`** — `data.records[]`：

```json
{ "id": 1, "assetId": 1, "assetCode": "A-0201", "assetName": "投影仪 EPSON CB-X06",
  "fromUserId": 2, "fromUserName": "张三", "toUserId": 3, "toUserName": "李四",
  "status": "PENDING", "applyReason": "…", "rejectReason": null,
  "createdAt": "2026-11-17 09:35:00", "decidedAt": null }
```

另返回 `data.pendingCount`（`incoming` 角标数，供侧栏使用）。

**16 PUT `/transfers/{id}/approve`** — 无请求体。事务内：`transfer.status=APPROVED` → `asset.holder_id=toUserId` → 写 `asset_record(TRANSFER, operator=fromUserId, target=toUserId, remark="转交至李四，应归还日不变")`。`due_date`、`renew_count` **不变**。

**17 PUT `/transfers/{id}/reject`** — `{ "rejectReason": "本周项目要用，无法转交" }`（必填 1–200 字）。

非当前审批人操作 → `40300`；状态非 `PENDING` → `40900`。

**33 GET `/votes/{id}`** — `data`：

```json
{ "id": 1, "title": "2026 年第四季度团建方案", "description": "…",
  "status": "PUBLISHED", "deadline": "2026-11-20 18:00:00",
  "totalVotes": 2, "votable": true,
  "myOptionId": 1,
  "showResult": true,
  "options": [ { "id": 1, "label": "千岛湖两日游", "votes": 1, "percent": 50.0 } ] }
```

| 字段 | 规则（Q4 决策） |
|---|---|
| `votable` | `PUBLISHED` 且未过截止 且 本人未投 |
| `myOptionId` | 已投则返回所选选项；未投为 `null` |
| `showResult` | 未投票且活动进行中 → `false`（投前隐藏票数）；投票后或活动关闭 → `true` |
| `options[].votes/percent` | `showResult=false` 时二者为 `null` |

**34 POST `/votes/{id}/vote`** — `{ "optionId": 2 }`

| 校验 | 失败 code |
|---|---|
| 活动未发布 / 已截止 / 已关闭 | `42200` |

## 12. 待实现约定（开发时必须遵守）

1. 控制器只做参数校验与调用 service，业务规则全部在 service（分层要求，PRD §7.2）。
2. 所有列表接口默认 `page=1&size=20`，前端同步 URL query（IA §7.10）。
3. 任何接口不得返回 `password` 字段；日志不打印令牌与密码。
4. 时间字段返回 `ISO` 格式字符串，不使用时间戳数字。
5. 新增接口必须先更新本文档（含错误码），再写代码。
