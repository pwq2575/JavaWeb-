## 3. 代码结构与分层

```
ers-backend/
├── pom.xml                      Spring Boot 3.2.5 / MyBatis-Plus 3.5.5 / JJWT 0.11.5 / easyexcel 3.3.4 / springdoc 2.3.0
└── src/main/
    ├── java/com/ers/
    │   ├── ErsApplication.java   @MapperScan + @EnableScheduling + startupBanner
    │   ├── common/               ApiCode / ApiResponse / PageResult / BizException / GlobalExceptionHandler / Const
    │   ├── security/             JwtService / JwtAuthenticationFilter / Rest*Handler / UserContext
    │   ├── config/               SecurityConfig / MybatisPlusConfig / DataInitializer / ConfigService
    │   ├── auth/                 AuthController / AuthService / dto
    │   ├── user/                 SysUser / SysUserMapper / UserController(/api/users/options)
    │   ├── asset/                AssetService(约 430 行) + AssetController + AdminAssetController + DTO
    │   ├── transfer/             TransferService + TransferController + DTO
    │   ├── room/                 SlotUtil + RoomService + RoomController + DTO
    │   ├── procurement/          ProcurementService + ProcurementController + DTO
    │   ├── vote/                 VoteService + VoteController + AdminVoteController + DTO
    │   ├── credit/               CreditService + MyCreditVO
    │   ├── my/                   MyService + MyController + WorkbenchVO
    │   ├── admin/                AdminUserService / AdminRoomService / AdminDashboardService + 4 Controller + DTO
    │   ├── export/               ExportService / ExportController（EasyExcel）
    │   └── job/                  CreditJob（逾期扣分 + 爽约扫描）
    └── resources/application.yml 端口/数据源/JWT/CORS/Jackson
```

分层约定：`Controller`（参数校验 + 取 `UserContext`）→ `Service`（业务规则 + 事务）→ `Mapper`（MyBatis-Plus）→ `entity`；对外只暴露 `dto`（record），实体不出 Controller。异常统一抛 `BizException(code, message)` 由 `GlobalExceptionHandler` 转 `ApiResponse`。

## 5. 关键实现决策

| # | 决策 | 理由 |
|---|---|---|
| 5.1 | JWT 无状态鉴权 + `JwtAuthenticationFilter`，不做 Session | 前后端分离，Nginx 后可水平扩展；`SecurityConfig` 统一放行 `/api/auth/login|register`，`/api/admin/**` 需 `ROLE_ADMIN` |
| 5.2 | 种子密码用 `password='__DEMO__'` 占位，`DataInitializer` 启动时 BCrypt 化 | 明文口令不进 Git，建库脚本可重复导入；`mvn spring-boot:run` 后即可用 123456 登录 |
| 5.3 | 借出/续借/归还全部用**条件更新**（`WHERE status=... AND holder_id=... AND renew_count=...`） | 不加锁实现乐观并发：影响行数 0 → `40900`「状态已变化，请刷新后重试」，避免两人同时借同一件 |
| 5.4 | 逾期扣分靠唯一键 `uk_credit_daily(user_id, reason, ref_type, ref_id, biz_date)` + `DuplicateKeyException` | 天然幂等：定时任务重跑、补跑都不会重复扣分，无需额外标记位 |
| 5.5 | 切片防重靠生成列唯一键 `uk_reservation_slot(room_id, reserve_date, active_slot)`（仅 BOOKED 占位） | 取消后 `active_slot=NULL` 可重订，DB 层防并发双订 |
| 5.6 | 待审批转交唯一键 `uk_transfer_pending(pending_asset_id)`（生成列仅 PENDING 有值） | 一资产同时只能有一条待审批，DB 兜底 + 业务层 40900 |
| 5.7 | 逾期**允许**续借（PRD D10），续借成功即停止后续扣分 | 用户有止损手段；已扣的分不回补，符合"责任已发生"的语义 |
| 5.8 | 投票「投前隐藏票数」：`showResult = 已投 || CLOSED`，否则 `votes/percent` 输出 null | 避免从众效应（IA Q4） |
| 5.9 | 投票截止用「读时惰性关闭」而不是定时器 | 少一个调度点，`GET /votes` 时把超期 PUBLISHED 批量置 CLOSED，语义等价且不会漏跑 |
| 5.10 | 转交是**独立事件**（写一条 `asset_record(TRANSFER)`），不是「归还 + 再借出」 | 责任链条可追溯、`due_date` 不变（IA B3、PRD §4.2(3)） |
| 5.11 | 统一响应体 `{code, message, data}`，错误也给同结构 | 前端 axios 拦截器一处处理；HTTP 状态码另由 `ApiCode.httpStatus` 映射 |
| 5.12 | 列表接口分页上限 100、排序白名单 | 防拖库式分页（PRD §8 安全） |

## 6. 踩坑与解法（环境类）

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| 6.1 | `mvn compile` 报 `找不到符号 getId()/setPassword()` | JDK 23+ 默认禁用隐式注解处理，Lombok 未生效 | pom 加 `lombok 1.18.38` + `maven-compiler-plugin` 的 `<proc>full</proc>` 与 `annotationProcessorPaths` |
| 6.2 | `mvn` 在用户终端 `command not found` | 安装前打开的终端未刷新环境变量 | 关掉重开 / 当前窗口 `$env:Path += ";...maven-3.9.9\bin"` / IDEA 直接开 `pom.xml` |
| 6.3 | `mvn wrapper:wrapper` 生成 `apache-maven-3-bin.zip` | `-Dmaven=3.9.9` 被解析成 `3`，且 wrapper 下载命中 TLS 故障 | 放弃 wrapper，改用 PATH；已删 `mvnw`/`.mvn` |
| 6.4 | 沙箱内 `~/.m2` 不可写（`resolver-status.properties 拒绝访问`） | 文件策略限制用户目录写入 | 构建加 `-Dmaven.repo.local=...\.tools\m2repo` |
| 6.5 | `Start-Process mvn ...` 起的服务随命令结束被杀 | 子进程生命周期跟随父进程 | 用后台 job 启动测试实例（8090），就绪探测 = 轮询 `/api/assets` 返回 401 |
| 6.6 | PowerShell 5.1 跑 UTF-8 无 BOM 脚本乱码 + `Unexpected token` | PS 5.1 按 ANSI 解码 | 冒烟脚本全 ASCII，中文只做断言值；复杂脚本再考虑用 .NET 写 UTF-8 BOM |
| 6.7 | `mysql -e "source D:/…中文路径/x.sql"` 报 `Failed to open file, error: 2` | mysql 客户端读不了中文路径 | `Push-Location db` 后用相对文件名 `source schema.sql`；或用 `cmd /c "... < schema.sql"` 重定向 |
| 6.8 | 端口冲突 `Port 8090 was already in use` | 上次测试实例未退 | `netstat -ano | findstr :8090` 取 PID → `Stop-Process -Id <pid> -Force` |
| 6.9 | `Set-Content` 写 `docs\` 中文路径被拒 | 沙箱写策略 | 中文路径文档一律用 write/edit 工具改，不用 shell 重定向 |
| 6.10 | `Set-Content -Encoding utf8` 给 `package.json` 写 BOM → `Invalid package.json` | PS 5.1 的 utf8 带 BOM | 一律用 write 工具写文件 |
| 6.11 | `pnpm install` 栈溢出、`pnpm build` 报 `Cannot find package 'esbuild'` | pnpm isolated 布局 + junction 解析在本机异常 | 前端改用 npm；文档同步改为 `npm install/dev/build` |
| 6.12 | 沙箱内 `vite build/dev` 报 `spawn EPERM` | 沙箱禁止 esbuild 子进程管道通信 | build 需单次 `danger-full-access` 授权；dev/preview 由用户在普通终端跑 |
| 6.13 | 编译 `BUILD SUCCESS` 但整条命令 `[exit code: 1]` | PowerShell 末尾管道/`netstat` 过滤返回非 0 | 以输出里的 `BUILD SUCCESS` 判断，不以 exit code 判断 |

## 7. 缺陷记录

| 编号 | 发现时间 | 现象 | 影响 | 状态 |
|---|---|---|---|---|
| D-01 | 2026-11-18 08:40 | 转交发起方与审批方**反向**：后端要求「当前持有者 A 选择接收人 B 并发起，B 审批」，与 PRD §4.2(3)「B 发起申请、A 审批」相反；前端因此把「发起转交」做成持有者选人 | 业务语义错误：现实场景是 B 到库房发现资产被 A 借走，向 A 申请接手；当前实现变成本人指定他人接手 | **已修复** 2026-11-18 09:00（方案 §7.1，验证 §8.3） |

### 7.1 D-01 修复方案（依据 PRD，不新增业务决策）

- 语义定稿（PRD §4.2(3) + API 契约 §4）：`B`（申请人，任意非持有者）在资产详情页发起「申请接手」→ 单据状态 `PENDING`、`from_user_id = 当前持有者 A`、`to_user_id = 申请人 B` → `A` 在「转交审批」页 `incoming` 中审批 → 同意则 `asset.holder_id = B`，`due_date`、`renew_count` 不变，写 `asset_record(TRANSFER, operator=A, target=B)`。
- 后端改动：`TransferCreateRequest` 去掉 `toUserId`（申请人不自选接收人，`toUserId` 由令牌推出）；`create()` 校验「资产已借出」「申请人不是持有者（否则 42200 你正持有该资产）」「无重复待审批（40900）」；`list()` 的 `outgoing` 改按 `to_user_id = 我` 查询（`incoming` 仍按 `from_user_id = 我`）。
- 前端改动：资产详情页动作栏按钮由「发起转交（选人）」改为「申请接手」（仅当资产被他人借出时出现）；转交审批页 Tab 文案改为「待我确认（我是持有者）」/「我发起的（等待对方确认）」；详情的待审批提示改为「X 申请接手」。
- 文档改动：API 契约 §4 #14 请求体与校验表改为 `{assetId, applyReason}`；删除「仅 ADMIN 可代发起」这条与 PRD 冲突的残留；PRD §4.2(3) 补一句字段映射（`from_user_id`=持有者、`to_user_id`=申请人），便于前后端对齐。
- 验证要求：重编译 → 8090 实例跑「李四申请接手张三在借资产 → 张三 incoming 可见 → 非张三审批 403 → 张三同意 → 持有者变李四、dueDate 不变 → 流转记录 1 条 TRANSFER」；另测「持有者自己申请 → 422」「重复申请 → 409」；前端 `npm run build` 通过。

### 8.2 D-01 定向验证（`.tmp/transfer_smoke.ps1`，21 断言全通过）

| # | 场景 | 期望 | 实测 |
|---|---|---|---|
| 1 | 张三（持有者）发起接手申请 | 422「你正持有该资产，无需申请接手」 | ✅ 422 / 42200 |

| 7 | 张三重复申请同一资产 | 409 已有待审 | ✅ |
| 8 | 张三（非审批人）同意 | 403「只有当前持有者可以审批该转交申请」 | ✅ 403 / 40300 |
