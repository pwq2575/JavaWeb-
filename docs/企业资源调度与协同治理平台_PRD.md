# 产品需求文档 (PRD) - 企业资源调度与协同治理平台 (ERS)

> 版本：**v1.3**（2026-11-17）｜ v1.3 修订 D13：技术栈改为**前后端分离**（Spring Boot 3 + Spring Security + JWT + MyBatis-Plus + MySQL 8；Vue 3 + Vite + Element Plus），不使用 JSP。v1.2 已同步 IA 阶段产品决策 D1-D12，并对齐课程任务要求（D13-D15、§7 技术架构、§8 安全要求、§9 课程要求对照）。IA 文档为 `docs/企业资源调度与协同治理平台-ia-2026-11-17.md`。

## 1. 背景与目标 (Background & Goals)

- **是什么**：一套面向中小型企业的轻量级资源管理系统，覆盖实体资产借还流转、场地预约、物料采购审批、企业文化投票与数据看板。
- **解决的真实问题**：
  - 实体资产借还去向不明，跨人转手后责任推诿、无法追溯；
  - 会议室预约冲突，同一时段被重复占用；
  - 物料缺口靠口头传递，采购无记录、无审批闭环；
  - 团建等文化活动组织效率低，意见收集靠群聊刷屏，无法量化。
- **业务目标**：让企业内每一件资产、每一个时间片、每一次采购、每一轮投票都有状态、有责任人、有记录、可导出。
- **用户价值**：员工借物/约场地路径短、责任清晰；管理员全局可视、可管、可导出。
- **衡量成功**：资产流转记录 100% 可追溯；场地预约零重复；逾期与爽约自动扣分闭环；核心台账可一键导出 Excel。

## 2. 目标用户 (Target Audience)

| 角色 | 画像 | 核心诉求 |
|---|---|---|
| **普通用户** | 企业员工，需要借办公资产、约会议室、参与团建投票 | 快速借用/预约、清楚自己的归还期限与信誉分、自助续借 |
| **管理员** | 行政/资源管家，维护资产与场地、审批采购、配置信誉规则 | 全局台账可视、审批高效、报表可导出、规则可配置 |

- **业务阶段**：MVP 从 0 到 1，两周敏捷交付。
- **核心策略**：优先保资产流转闭环与场地防重两条主线，信誉机制做双渠道自动扣分，看板与导出满足演示与实用。

## 3. 需求范围 (Scope)

### In Scope（本次覆盖必做）

- **账号与鉴权**：注册、登录、**JWT 令牌**（Spring Security 认证 + 无状态令牌）、角色拦截、密码加密存储；**用户管理**（管理员）：新增用户、删除用户、查询、改角色、重置密码（D14 对齐课程"管理员增删查改"要求）。
- **资产台账与流转**：单件资产 CRUD；借出（固定 3 天归还期）；归还；**自助续借**（+1 天/次，最多 3 次）；**转交**（B 发起，当前持有者 A 审批决定）。
- **信誉机制**：资产逾期**每日扣 5 分**（续借成功后停止）；会议室**爽约一次性扣 5 分**；阈值默认 60 分、管理员可配（以 10 为跨度）；低于阈值限制借用高价值资产。
- **场地预约**：固定 30 分钟切片；唯一索引 `(room_id, date, time_slot)` 防重；开始前可自由取消；爽约判定；**场地管理**（管理员）新增/编辑/删除/启停用（D14）。
- **采购审批**：用户提交申请（名称、理由）；管理员同意入库或驳回；管理员可删除已驳回申请（D14）。
- **文化投票**：管理员发布方案并设截止时间；每人一次、不可修改；到点自动停收；管理员可手动提前关闭；ECharts 饼图展示得票比例；**活动草稿态**可编辑/删除，发布后仅可关闭（D15）。
- **数据导出与看板**：资产台账 Excel 导出（EasyExcel）；热门资产借用排行图；投票饼图。
- **技术架构**：**前后端分离**。后端 Java 17 + Spring Boot 3.2 + Spring MVC + Spring Security 6 + JWT + MyBatis-Plus + MySQL 8；前端 Vue 3 + Vite 5 + Element Plus + Pinia + Vue Router 4 + Axios + ECharts；分层架构，数据存于 MySQL 本地实例（详见 §7）。

### Out of Scope（不涉及 / 未来做）

- 密码找回、第三方登录。
- 批量库存型资产的转交流程与领用流程（本期均不实现，Q7 已决；台账只维护单件资产，批量消耗品不录入系统）。
- 站内消息中心、邮件/短信通知（Q2 已决：用工作台待办 + 导航角标替代，列入下一期）。
- 员工端完整移动端适配：桌面优先（≥1280px），768-1280 可用，≤768 仅保证可滚动可点击（Q11 已决）。
- 信誉分恢复机制（不自动回升、不手动加回）。
- 资产折旧计算、扫码借还。
- 场地自由起止时间、预约审批流、日历视图、取消太晚扣分。
- 采购自动入库联动、多级审批。
- 匿名投票、投票修改、截止时间外的人工干预。
- 个人借用凭证 PDF 导出、场地使用热力图（时间紧可降级）。
- **类图 / 时序图 / 部署图**：本 PRD 只定分层与模块边界（§7.2），详细类图与时序图在实现阶段按需产出，不进需求文档。

## 4. 核心功能详述 (Functional Requirements)

### 4.1 账号与鉴权模块

- **模块 / 页面**：注册页、登录页、前端路由守卫 + 后端 Spring Security 过滤器链。
- **触发条件 / 前置条件**：未登录访问受保护页面 → 前端路由守卫跳登录；未携带有效令牌调用受保护接口 → 401；注册需唯一账号。
- **预期行为与校验规则**：
  - 注册：账号唯一校验；密码加密存储（BCrypt）；默认角色为普通用户、信誉分 100。
  - 登录：`POST /api/auth/login` 校验凭证 → 签发 **JWT**（2 小时有效，含 `userId`、`role`）→ 前端存入 Pinia + localStorage，后续请求由 Axios 拦截器加 `Authorization: Bearer <token>`；后端由 Spring Security 的 JWT 过滤器校验令牌与角色。
  - 普通用户不可访问管理端接口（`/api/admin/**` 需 `ROLE_ADMIN`）；管理员可访问全部接口。
  - **管理员账号与用户管理（Q9 / D14 已决）**：数据库种子写入一个 `admin` 账号（不通过注册产生）；管理员可在「用户管理」中**新增用户、删除用户（不可删自己、不可删有在途借用者）、查询（账号/角色/信誉分/注册时间，支持关键词搜索）、修改角色、重置密码**；角色变更与删除需二次确认。
  - Edge Case：令牌过期/无效 → 接口返回 401 → 前端清空本地令牌并跳登录页，`redirect` 参数保留原目标路由；账号重复 → 返回明确错误。

### 4.2 资产台账与流转模块（核心业务）

- **模块 / 页面**：资产列表、资产详情、我的借用、转交审批。
- **触发条件 / 前置条件**：资产在库方可借出；用户信誉分满足高价值资产限制。
- **预期行为与校验规则**：

  **（1）借出**
  - 前置：资产状态为“在库”；用户信誉分 ≥ 阈值，或资产价值 ≤ 高价值阈值（默认 500 元，可配）。
  - 行为：确认借出 → 状态变“借出”，记录当前持有者；`due_date = 借出时刻 + 3 天`。
  - Edge Case：信誉分 < 阈值且资产价值 > 阈值 → 拒绝并提示；资产已被借出 → 拒绝。

  **（2）续借（自助，无需审批）**
  - 前置：借用未逾期（或逾期后仍允许，但停止扣分）；累计续借天数 < 3 天；**无待处理的转交申请**。
  - 行为：`due_date += 1 天`，续借次数 +1。
  - Edge Case：存在待处理转交 → 拒绝续借，提示先处理转交；续借已达 3 天 → 拒绝。

  **（3）转交（仅单件唯一资产）**
  - 前置：资产为单件唯一资产、状态“借出”、B 向当前持有者 A 发起。
  - 行为：转交申请状态“待 A 确认”。
  - A 的审批选项：
    - **同意转交** → 持有者变为 B，`due_date` 不变，责任转移，转交记录入流转日志。
    - **拒绝转交** → 申请关闭，A 继续持有，A 可自行续借。
  - Edge Case：批量消耗品 → 不支持转交，走领用；A 拒绝后 B 可再次申请（本期不做申请次数限制）。
  - **页面与入口（Q1 已决）**：B 在**资产详情页**发起转交；A 在独立**「转交审批」页**处理（「待我确认」/「我发起的」两个 Tab）。转交审批页不提供"新建转交"入口。

  **（4）归还**
  - 行为：持有者确认归还 → 资产状态回“在库”、清空当前持有者、流转记录闭环。
  - Edge Case：归还时若存在逾期，先完成归还，逾期扣分已由定时任务执行，不重复扣。

  **（5）流转记录**
  - 每次借出、转交、归还均写入 `asset_record`，含操作人、时间、动作类型，供追溯与导出。

  **（6）字段校验（Q12 已决）**
  - 资产「价值」必填且 ≥0（高价值判定依赖它）；旧数据缺失按 0 处理，不触发高价值限制。

  **（7）台账维护（管理员 CRUD，D14 已决）**
  - **增**：名称、编号（唯一）、分类、价值、位置、启用状态。
  - **查**：按名称/编号、状态、分类、持有者、是否逾期筛选；分页；可查看单资产流转历史。
  - **改**：编辑基础信息；借出中的资产不可直接把状态改为「在库」，须走归还流程。
  - **删**：仅从未产生借出/转交记录的资产可物理删除；已有流转记录的资产只可「停用」（下架），保留审计。

### 4.3 信誉机制模块

- **模块 / 页面**：信誉分管理（管理端）、借用限制校验（业务层）、定时任务。
- **触发条件 / 前置条件**：定时任务每日执行；借用时校验。
- **预期行为与校验规则**：
  - **渠道 1 资产逾期**：定时任务扫描 `status=借出 AND due_date < now AND 当日未扣分` → 扣 5 分，标记当日已扣；续借成功后 `due_date` 更新，后续不再触发扣分。
  - **渠道 2 会议室爽约**：预约结束仍未标记使用且未提前取消 → 一次性扣 5 分，标记已处理。
  - 信誉分最低 0 分，不出现负数。
  - 阈值：默认 60，管理员可配，跨度 10（如 50/60/70/80）。
  - 限制：信誉分 < 阈值 → 不可借用价值 > 高价值阈值（默认 500，可配）的资产；不影响低价值资产、场地预约、投票。
  - Edge Case：同一逾期记录当日重复扫描 → 靠“当日已扣”标记去重；续借后停止扣分。

### 4.4 场地预约防冲突模块

- **模块 / 页面**：场地列表、预约页、我的预约。
- **触发条件 / 前置条件**：登录用户可预约；场地由管理员维护。
- **预期行为与校验规则**：
  - 预约：选择场地 + 日期 + 30 分钟切片 → 插入 `reservation`。
  - **防重**：唯一索引 `(room_id, reserve_date, active_slot)`（`active_slot` 为生成列，仅 `BOOKED` 占位，取消后释放）；插入冲突捕获异常 → 返回“该时段已被预约”。
  - 取消：预约开始前可自由取消 → 释放切片，不扣分。
  - 爽约：预约结束仍未标记使用且未取消 → 定时任务判定爽约，扣 5 分。
  - **预约视图与时段（Q3 / Q10 已决）**：仅提供**单日**「场地 × 30 分钟切片」网格，不做月历/时间轴视图；营业时段 **09:00-18:00**；可预约**未来 14 天**（含今天）。
  - **场地管理（管理员，D14 已决）**：新增/编辑场地（名称、位置、容量、启用状态）；删除仅限**无未来预约**的场地；停用后不可被新预约，已有预约不受影响。
  - Edge Case：并发抢同一时段 → 数据库唯一索引兜底，仅一条成功；重复预约同一时段 → 拒绝。

### 4.5 物料采购与审批模块

- **模块 / 页面**：采购申请页、审批列表（管理端）。
- **触发条件 / 前置条件**：登录用户可提交；管理员审批。
- **预期行为与校验规则**：
  - 提交：填写名称、理由 → 状态“待审批”。
  - **申请字段（Q6 已决）**：严格只有「名称 + 理由」（理由 ≤200 字），不含数量/金额/期望时间。
  - 审批：管理员“同意入库” → 状态“已入库”（本期不自动联动资产台账，仅状态流转）；“驳回” → 状态“已驳回”。
  - **自审（Q8 已决）**：管理员可审批自己提交的申请，页面标注“申请人 = 审批人”。
  - **数据维护（D14 已决）**：管理员可删除「已驳回」申请（已入库不可删，保留审计）；已审批不可重复审批。
  - Edge Case：已审批的申请不可重复审批；驳回需可填驳回理由。

### 4.6 企业文化与协同互动模块

- **模块 / 页面**：投票活动页、管理端发布页、ECharts 饼图。
- **触发条件 / 前置条件**：管理员发布活动并设截止时间；登录用户可投票。
- **预期行为与校验规则**：
  - 发布：管理员创建活动 + 多个方案 + 截止时间。**方案发布后不可修改/追加，仅可提前关闭**（Q5 已决）。
  - **活动生命周期（Q5 / D15 已决）**：创建后先为「草稿」，草稿可编辑标题/说明/方案/截止时间，也可删除；发布后不可编辑，仅可提前关闭；删除活动仅限草稿（已投票活动只能关闭）。
  - 投票：每人每活动仅一次，不可修改；校验 `now < deadline` 且活动未关闭。
  - 截止：到点自动停收；管理员可手动提前关闭（状态改“已结束”）。
  - 展示：ECharts 饼图动态展示各方案得票比例。**投票前不显示各方案票数；用户投票后与活动结束后均可见；管理员始终可见**（Q4 已决）。
  - Edge Case：已投票用户再次投票 → 拒绝；活动已结束 → 拒绝；截止时间已过 → 拒绝。

### 4.7 数据导出与可视化模块

- **模块 / 页面**：报表导出入口（管理端 + 个人）、数据看板。
- **触发条件 / 前置条件**：管理员可导出全局台账；用户可导出个人借用记录。
- **预期行为与校验规则**：
  - Excel 导出：EasyExcel 实现资产台账、个人借用记录导出下载。
  - 看板：ECharts 渲染热门资产借用排行、投票得票饼图。
  - Edge Case：无数据导出 → 返回空表头文件而非报错；大数据量 → 本期不做分页导出优化。

## 7. 技术架构与实现约束 (Technical Architecture)

> 对齐课程要求：① 基于 Java 技术（SSM / Spring MVC / Spring Boot / Spring / MyBatis）；② 多层架构；③ 所有数据基于数据库文件存储。
> **D13 v1.3 修订**：采用**前后端分离**（后端 REST API + 前端 Vue 3 SPA），**不使用 JSP**。JSP 属课程列举技术中"知悉但不采用"的一项，理由是课程同时要求"技术架构好"，而当前企业后台主流为前后端分离；SSM / Spring MVC / Spring Boot / Spring / MyBatis 全部真实使用（用户 m00615 已确认）。

### 7.1 技术选型（D13 已决）

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 / 构建 | Java 17 + Maven 3.9；Node 24 + npm | 后端 Java 单体，前端独立构建 |
| 后端框架 | Spring Boot 3.2.x（内嵌 Spring MVC、Spring Core） | 课程列举的 Spring / Spring MVC / Spring Boot 由 Boot 统一承担 |
| 持久层 | MyBatis-Plus 3.5（底层 MyBatis；单表 CRUD 用 Wrapper，多表与报表保留 XML） | 满足"灵活运用 MyBatis"，同时减少样板 SQL |
| 鉴权 | Spring Security 6 + JWT（jjwt）+ BCrypt | 无状态令牌，前后端分离标配 |
| 数据库 | MySQL 8.0（InnoDB，本地实例，数据文件落盘） | 满足"数据基于数据库文件存储"；不依赖外部云服务 |
| 缓存（可选） | Redis 7（令牌黑名单 / 字典缓存） | 时间紧可省，接口须能在无 Redis 时降级 |
| 前端框架 | Vue 3（Composition API + `<script setup>`）+ Vite 5 | 当前企业后台主流组合 |
| 前端 UI / 状态 | Element Plus + Pinia + Vue Router 4 + Axios | 与参考站西柚 ITAM 同生态，视觉规范可直接借鉴 |
| 图表 | ECharts 5（按需引入） | 饼图 / 条图 |
| 导出 | EasyExcel（后端生成，前端以 blob 下载） | — |
| 测试 | JUnit 5 + Spring Boot Test + Mockito + MockMvc；接口冒烟用 Apifox 集合 | 对齐课程"集成测试"要求 |
| 部署 | 前端 `npm run build` → Nginx 静态托管；后端 `java -jar` | 单机可跑；开发期 Vite proxy 转发 `/api` |

- **不采用 JSP**：服务端渲染在组件化、路由、状态管理与前后端协作效率上均落后于 Vue 3 + Element Plus，且企业已无新建 JSP 页面（JSP 仅存在于存量维护），故按用户要求改前后端分离。
- **不强制 Spring Cloud**：单体规模（23 个页面、6 个业务域）引入注册中心/网关/配置中心是负收益；答辩口径为"知悉微服务拆分，按交付规模选择单体"。若课程明确要求体现，可加 Spring Cloud Alibaba Nacos（注册中心）+ Spring Cloud Gateway（路由）做最小演示，业务代码不变。
- **前后端同仓库并列**：`ers-backend/`（Maven）与 `ers-web/`（npm）；开发期前端 5173、后端 8080。

### 7.2 分层架构

```text
ers-backend  (com.ers)
├── controller     REST 接口，参数校验（@Valid），返回 Result<T>
├── service        业务规则（借出/续借/转交/归还、预约防重、信誉扣分、审批、投票）
│   └── impl
├── mapper         MyBatis-Plus BaseMapper + XML（复杂 SQL 只出现在这里）
├── entity / dto / vo
├── security       JWT 过滤器、UserDetailsService、SecurityConfig、@PreAuthorize
├── config         跨域、MyBatis-Plus、全局异常、Jackson、OpenAPI
├── job            定时任务（逾期扣分、爽约判定、投票截止）
└── common         Result、PageResult、错误码、常量、工具类

ers-web  (src)
├── api            Axios 实例 + 按域拆分的接口文件
├── router         Vue Router + 路由守卫（登录态、角色）
├── stores         Pinia（user、dict）
├── views          按页面 ID 组织（见 IA §4），如 views/asset/
├── components     通用表格、筛选栏、状态标签、图表容器
└── utils          日期、权限指令 v-permission、下载 blob
```

- 调用方向固定 `controller → service → mapper`；禁止 controller 直连 mapper、禁止 mapper 承载业务判断。
- 接口约定：统一 `Result<T>{code, msg, data}`；分页 `PageResult<T>{records, total, current, size}`；HTTP 状态码与业务码并用（401 未登录、403 无权限、422 校验失败）。
- 全局异常处理器：业务异常 → 友好文案 + 业务码；参数校验异常 → 422 + 字段级错误数组（前端 Element Plus 表单回显）。

### 7.3 请求与鉴权约束

- Spring Security 过滤器链：`/api/auth/**` 放行；其余 `/api/**` 需 `Authorization: Bearer <token>`；`/api/admin/**` 需 `ROLE_ADMIN`（路径规则 + `@PreAuthorize` 方法级双层校验）。
- 令牌：JWT 2 小时有效（载荷含 `userId`、`role`），前端存 Pinia + localStorage；过期或非法 → 401 → 前端路由守卫跳登录并带 `redirect`。
- 写操作一律 `POST` / `PUT` / `DELETE` + 服务端校验（Jakarta Validation）；重复提交由业务状态机与唯一索引兜底。
- 列表接口统一参数：`page`、`size`、`keyword`、排序字段白名单；筛选条件走 query，并同步到前端 URL query，保证刷新、分享、前进后退可复现。
- 跨域：开发期 Vite proxy（`/api` → `localhost:8080`）；生产 Nginx 同源反代，不开放 `*` CORS。

### 7.4 交付物与运行

- 建表脚本 `db/schema.sql` + 演示数据 `db/data.sql`（含种子 admin、示例资产、场地与投票活动）。
- 运行：后端 `mvn spring-boot:run`（8080，接口文档 `/swagger-ui.html`）；前端 `npm run dev`（5173，proxy 到 8080）、`npm run build`（产物 `dist/` 由 Nginx 托管）；数据库连接见 `application.yml`。
- 集成测试：借出→续借→转交→归还、场地并发防重、信誉扣分与阈值限制、采购审批、投票唯一性各至少 1 条 MockMvc 冒烟用例；关键 service 用 Mockito 单测。

## 8. 安全要求 (Security)

| 风险 | 要求 |
|---|---|
| SQL 注入 | MyBatis-Plus Wrapper / XML 全部 `#{}` 参数绑定；排序字段与动态表名走白名单枚举，禁止字符串拼接 |
| XSS | Vue 模板默认转义；**禁止 `v-html` 渲染用户输入**；后端只返回 JSON，不拼 HTML；导出内容做公式注入转义（`=` 开头加 `'`） |
| CSRF | 令牌走 `Authorization` 头，不依赖 Cookie 认证，天然免疫 CSRF；若改 Cookie 存储必须补 CSRF Token 与 SameSite |
| 越权 | Spring Security 路径规则 + `@PreAuthorize` 双层；业务层校验资源归属（仅持有者可续借/归还/发起转交） |
| 密码 | BCrypt 存储；登录失败统一提示"账号或密码错误"，不区分账号是否存在；注册/改密强度校验 |
| 令牌 | 2 小时过期；退出即前端清空令牌（可选 Redis 黑名单）；本期不做刷新令牌；`redirect` 仅允许站内相对路径 |
| 接口 | `@Valid` 参数校验；统一异常处理不返回堆栈；可选限流（Redis/Guava 计数器） |
| 导出 | 按当前用户权限过滤数据；`Content-Disposition` 文件名不含用户输入 |
| 配置与数据 | 数据库账号、JWT 密钥走环境变量或 `application-prod.yml`（不进仓库）；`.env`、`dist/`、`target/` 忽略 |
