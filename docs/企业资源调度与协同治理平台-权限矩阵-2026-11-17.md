# 权限矩阵 — 企业资源调度与协同治理平台 (ERS)

## 0. 元数据

| 字段 | 值 |
|---|---|
| 文档类型 | 权限矩阵 / 访问控制设计 |
| 版本 | v1.0 — Frozen（2026-11-17） |
| 依赖 | PRD v1.3 §4.1、IA v1.3 §4 页面清单与 §7.10、API 契约 v1.0 |
| 实现载体 | 前端 Vue Router `meta.roles` + 指令 `v-permission`；后端 Spring Security `authorizeHttpRequests` + `@PreAuthorize` |
| 原则 | **前端守卫只做体验，后端注解才是权限边界**；所有权限判定在接口层生效，不信任前端 |

## 1. 角色定义

| 角色 | 枚举值 | 说明 | 获取方式 |
|---|---|---|---|
| 匿名 | —（无令牌） | 未登录访客，仅可访问登录/注册页 | 无 |
| 普通用户 | `USER` | 员工：借物、约场地、提交采购与审批他人的转交、投票、查看个人数据 | 注册接口（唯一入口） |
| 管理员 | `ADMIN` | 管理员也是员工，拥有全部 `USER` 能力 + 全部管理接口 | 数据库种子（`db/data.sql`）或由管理员在 P-ADM-07 授权 |

> **不做双后台**（IA §3 结论）：管理员登录后仍落在同一套应用壳，管理入口以「管理」分组呈现；`ADMIN` 的可见菜单 = 员工菜单 + 管理分组。

### 2.1 Vue Router 路由配置示例

```js
const routes = [
  { path: '/login', component: Login, meta: { public: true } },
  { path: '/register', component: Register, meta: { public: true } },
  { path: '/', component: Home, meta: { requiresAuth: true } },
  { path: '/assets', component: AssetList, meta: { requiresAuth: true } },
  { path: '/assets/:id', component: AssetDetail, meta: { requiresAuth: true } },
  { path: '/admin', component: AdminOverview, meta: { requiresAuth: true, roles: ['ADMIN'] } },
  { path: '/admin/users', component: AdminUsers, meta: { requiresAuth: true, roles: ['ADMIN'] } },
  // …其余管理页同理
  { path: '/:pathMatch(.*)*', component: SysNotice, meta: { public: true } },
]

router.beforeEach((to) => {
  const auth = useAuthStore()
  if (!to.meta.public && !auth.token) return { path: '/login', query: { redirect: to.fullPath } }
  if (to.meta.roles && !to.meta.roles.includes(auth.role)) return { path: '/sys/403' }
  if (to.meta.public && auth.token && (to.path === '/login' || to.path === '/register')) return { path: '/' }
  return true
})
```

## 3. 接口级权限矩阵

图例：`匿名` 无需令牌 · `登录` 任意已登录用户 · `ADMIN` 仅管理员 · 数据范围见 §4。

### 3.1 认证 `/auth`

| 接口 | 方法 | 权限 |
|---|---|---|
| `/auth/register` | POST | 匿名（仅创建 `USER`，**不接受 role 参数**） |
| `/auth/login` | POST | 匿名 |
| `/auth/me` | GET | 登录 |
| `/auth/logout` | POST | 登录 |

### 3.2 资产 `/assets`

| 接口 | 方法 | 权限 | 数据范围 / 附加条件 |
|---|---|---|---|
| `/assets` | GET | 登录 | 全员可见（停用资产仅 `ADMIN` 可见） |
| `/assets/{id}` | GET | 登录 | 全员可见 |
| `/assets` | POST | ADMIN | — |
| `/assets/{id}` | PUT | ADMIN | — |
| `/assets/{id}` | DELETE | ADMIN | 仅无流转/无借出记录 |
| `/assets/{id}/borrow` | POST | 登录 | 本人借；管理员可代借（`userId` 参数） |
| `/assets/{id}/return` | POST | 登录 | 仅当前持有者或 ADMIN |
| `/assets/{id}/renew` | POST | 登录 | 仅当前持有者 |
| `/assets/{id}/records` | GET | 登录 | 全员可读（资产审计公开） |

### 3.3 转交 `/transfers`

| 接口 | 方法 | 权限 | 数据范围 / 附加条件 |
|---|---|---|---|
| `/transfers` | POST | 登录 | 发起人须为当前持有者（或 ADMIN 代发起） |
| `/transfers` | GET | 登录 | `incoming`=当前持有者为审批人；`outgoing`=发起人为本人；ADMIN 可 `box=all` |
| `/transfers/{id}/approve` | PUT | 登录 | **仅 `transfer.from_user_id` = 当前用户**（ADMIN 不越权代批，除非显式代管） |
| `/transfers/{id}/reject` | PUT | 登录 | 同上 |

### 3.4 个人 `/my`

| 接口 | 方法 | 权限 | 数据范围 |
|---|---|---|---|
| `/my/borrows` | GET | 登录 | 强制 `holder_id = 当前用户` |
| `/my/reservations` | GET | 登录 | 强制 `user_id = 当前用户` |
| `/my/credit` | GET | 登录 | 强制 `user_id = 当前用户` |
| `/my/workbench` | GET | 登录 | 聚合本人数据 |

> 个人接口**不接受** `userId` 参数；后端从令牌取 `sub`，杜绝 IDOR。

### 3.5 场地与预约

| `/reservations/{id}/cancel` | PUT | 登录 | 仅 `user_id = 本人` |
| `/reservations/{id}/use` | PUT | 登录 | 仅 `user_id = 本人` |

### 3.6 采购 `/procurements`

| 接口 | 方法 | 权限 | 数据范围 |

| `/procurements` | GET | 登录 | USER：`applicant_id = 本人`；ADMIN：全部（可 `status` 筛选） |

## 4. 数据范围规则（后端强制）

| 资源 | 普通用户可见范围 | 后端实现方式 |
|---|---|---|
| 资产 | 全部 `ACTIVE` 资产；不可见 `DISABLED` | `QueryWrapper.ne("status","DISABLED")` 且角色为 USER 时强制 |
| 借用记录 | 本人持有 + 本人历史 | `asset_record` 按 `operator_id = 当前用户 OR target_user_id = 当前用户` |
| 转交 | 待我审批（`from_user_id=我`，`PENDING`）+ 我发起的（`to_user_id=我`） | `transfer_request` 条件拼接 |
| 预约 | 本人的预约明细；他人预约仅暴露「被占用」布尔 | 列表返回 `reservedByMe`，`user_id` 脱敏 |
| 采购 | `applicant_id = 本人` | 服务端覆盖参数，忽略前端传入的 `userId` |
| 信誉流水 | 本人 `credit_log` | 同上 |
| 用户资料 | 本人（`/auth/me`）；其他用户仅显示姓名（持有人在资产详情中出现） | 不做用户目录浏览页 |

**IDOR 防护统一写法**（示例）：

```java
@PreAuthorize("#asset.holderId == authentication.principal.id or hasRole('ADMIN')")
public void returnAsset(Asset asset) { ... }
```

## 5. 业务规则型权限（非角色，但会拒绝操作）

| 规则 | 触发条件 | 返回 | 说明 |
|---|---|---|---|
| 低信誉限制借高价值 | `credit < credit.threshold` 且 `asset.value >= high_value.threshold` | `40301` | 低价值资产、场地、投票不受限（PRD 4.3） |
| 账号停用 | `sys_user.status = 'DISABLED'` | `40100` | 登录与已签发令牌均失效（过滤器校验状态） |
| 令牌过期 | `exp < now` | `40100` | 前端清令牌跳登录 |
| 续借上限 | `renew_count >= 3` | `42200` | — |
| 转交审批人错位 | `from_user_id != 当前用户` | `40300` | — |
| 审批自己提交的采购 | 允许但需勾选「自审」 | 200 | 记录 `self_approved = true` 供审计 |

## 6. 前后端双重实施对照

| 层 | 机制 | 覆盖点 |
|---|---|---|
| 前端 · 路由 | `meta.requiresAuth` / `meta.roles` + `beforeEach` | 页面级不可达 |
| 前端 · 指令 | `v-permission="'admin'"` 控制按钮显隐 | 按钮级隐藏（非安全边界） |
| 前端 · 菜单 | 按角色过滤菜单项（IA §3 B1：6 项员工导航 + 管理分组） | 入口不可见 |
| 后端 · 过滤器链 | `requestMatchers("/api/auth/**").permitAll()`、`/api/admin/**`.hasRole("ADMIN")、其余 authenticated | 路径级 |
| 后端 · 方法注解 | 每个 Controller 方法 `@PreAuthorize("hasRole('ADMIN')")` 或资源归属表达式 | 方法级 |
| 后端 · 数据过滤 | Service 层强制拼接 `user_id` 条件（见 §4） | 行级 |
| 后端 · 唯一约束 | `uk_transfer_pending`、`uk_reservation_slot`、`uk_vote_user`、`uk_credit_daily` | 并发安全兜底 |

`SecurityConfig` 骨架：

```java
http.csrf(csrf -> csrf.disable())
    .sessionManagement(s -> s.sessionCreationPolicy(STATELESS))
    .authorizeHttpRequests(a -> a
        .requestMatchers("/api/auth/login", "/api/auth/register", "/swagger-ui/**").permitAll()
        .requestMatchers("/api/admin/**").hasRole("ADMIN")
        .anyRequest().authenticated())
    .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class);
```

## 8. 变更规则

1. 新增接口必须在本文档 §3 登记权限与数据范围，并在 Controller 上加 `@PreAuthorize`。
2. 新增页面必须在 §2 登记角色与数据范围，路由 `meta` 同步。
3. 任何「前端判断权限、后端不校验」的实现视为缺陷（P1）。
4. 演示账号（`db/data.sql`）：`admin / 123456`（ADMIN）、`zhangsan / 123456`（USER，信誉 100）、`lisi / 123456`（USER，信誉 85，有逾期）、`wangwu / 123456`（USER，信誉 55，低于阈值）。
